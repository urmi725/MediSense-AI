# 🩺 MediSense AI — Healthcare Diagnosis Assistant

**An end-to-end ML + full-stack web application that predicts likely conditions from symptoms, scores risk, flags emergencies, and tracks a user's health-check history and analytics.**

> ⚠️ **This is an educational/academic project, not a medical device.** It does not
> replace professional medical advice, diagnosis, or treatment. Always
> consult a qualified healthcare provider. The dataset is **synthetically
> generated** — see [About the dataset](#-about-the-dataset).

## ✨ Features

| Category | What it does |
|---|---|
| 🧠 ML-based prediction | RandomForestClassifier (180 trees) trained on **73 conditions** and **140 symptoms**, returns top-3 conditions with confidence % |
| 📈 Model validation | 5-fold stratified cross-validation, per-class precision/recall/F1, confusion matrix, and feature-importance ranking — all auto-generated by `train_model.py` |
| 🚦 Risk scoring | Combines age, fever, breathing symptoms, existing conditions, and severity into Low / Medium / High |
| 🚨 Emergency detection | Rule-based alerts for 10 critical symptom combinations (e.g. chest pain + shortness of breath, jaundice + high fever) |
| 👤 User accounts | Sign up / log in (hashed passwords via Werkzeug); guests can still use the checker without an account |
| 🕒 Personal history | Every check saved to SQLite, scoped per-user; guests see only their own device's checks |
| 📊 Analytics dashboard | Chart.js visualizations: model performance stats, most-predicted conditions, risk distribution, top reported symptoms, feedback helpfulness rate |
| 👍 Feedback loop | "Was this helpful?" widget on every report, aggregated into the dashboard |
| ⬇️ CSV export | Download your full check history as a spreadsheet-ready CSV |
| 🌦️ Seasonal health tips | India-focused awareness page (monsoon/winter/summer disease risks + prevention tips) |
| ⚠️ Honest scope handling | Quick fever buttons (no thermometer needed), a low-confidence warning when symptoms don't match the model well, and a "no results" hint for voice/text search |
| 💊 Detailed medication guidance | Each report shows common OTC options, what to avoid, a prescription note, and an "urgent care needed" flag when relevant |
| 🚑 Emergency hospital finder | Uses the browser's live GPS location + an interactive map (Leaflet/OpenStreetMap) to find and route to the nearest hospitals — no API key required, works out of the box |
| 👨‍⚕️ Specialist directory | Curated real Agra/Mathura hospital & doctor listings, **plus optional live search** via the Google Places API |
| 🎤 Voice-assisted search | Speak your symptoms — uses the browser's built-in Web Speech API |
| 🌗 Dark mode | Toggle + persisted via localStorage |
| 🖨️ Printable report | One click to print or save the results as a PDF |
| 📱 Custom, responsive UI | Distinct color system, Google Fonts, light/dark themes, no framework bloat |

## 🚀 Quick start

```bash
cd AI_Healthcare_Diagnosis_Assistant
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

# generate the synthetic dataset
python generate_dataset.py

# train the model (prints accuracy, CV score, confusion matrix, feature importances)
python train_model.py

# run the web app
python app.py
```

Then open **http://localhost:5000** in your browser.

## ⚙️ How it works

1. **Patient input** — `index.html` collects age, gender, weight, height, temperature, duration, existing conditions, and a searchable (and voice-searchable) symptom checklist.
2. **Encoding** — `predict.py:encode_symptoms()` converts selected symptoms into the multi-hot vector the model expects.
3. **Feature engineering** — BMI and BMI category, plus a symptom severity score, are computed.
4. **ML inference** — a `RandomForestClassifier` (180 trees, class-balanced) returns probabilities across all 73 diseases; the top 3 are shown with confidence percentages.
5. **Risk engine** — `calc_risk()` combines age, fever, breathing symptoms, existing conditions, and severity into a score mapped to Low / Medium / High.
6. **Emergency detection** — `detect_emergency()` flags 10 critical symptom combinations with an immediate warning banner.
7. **Recommendation engine** — looks up precautions, informational medication notes, and the recommended specialist for the top predicted condition, with a link into the sample doctor directory.
8. **Accounts + history** — if logged in, the check is tied to the user's account; guests get a device-local history. Every report supports "was this helpful?" feedback and CSV export.
9. **Analytics dashboard** — aggregates the user's own history (disease frequency, risk distribution, top symptoms, feedback rate) alongside the model's own validation metrics, rendered with Chart.js.

## 📊 About the dataset

`generate_dataset.py` creates a **synthetic** dataset of **~19,000 patient rows**
across **73 conditions** and **140 symptoms**, sampled from illustrative
symptom-probability profiles with added noise. The disease list intentionally
includes conditions with a high reported patient burden in India (Tuberculosis,
Typhoid Fever, Hepatitis A, Chikungunya, Cholera, Dengue, Malaria, Type 2
Diabetes, Hypertension, Anemia) alongside common global conditions (colds, flu,
COVID-19, migraine, asthma, arthritis, thyroid disorders, GERD, UTIs, and more).

**For anything beyond a demo/academic project**, swap in a real, licensed
clinical dataset reviewed by a medical professional, drop it in as
`dataset/diseases.csv`, and re-run `train_model.py`.

**Current demo model:** ~62–64% held-out and cross-validated accuracy on a
**73-way classification problem** (random guessing would be ~1.4%). Accuracy
is naturally lower than a smaller model because many conditions intentionally
share overlapping symptoms (e.g. Asthma/Bronchitis/COPD, or Gastroenteritis/
Food Poisoning/Cholera) — this mirrors real diagnostic difficulty and is why
the app also shows a low-confidence warning when no condition matches well.
Full metrics are written to `model/metrics.json` and shown on the in-app Dashboard.

## 🔴 Enabling live doctor search (optional)

By default, `/find-doctor` shows a curated list of real, well-reviewed hospitals
and specialists in Agra and Mathura. You can optionally turn on **live search**,
which queries the Google Places API in real time for any specialty/city the
person types in.

1. Create a free Google Cloud account at https://console.cloud.google.com (a new account gets free credit, and Places API usage is very cheap at low volume).
2. Create a project, then enable the **Places API**.
3. Create an API key under "APIs & Services → Credentials".
4. Set it as an environment variable before running the app:
   - **Windows (PowerShell):** `$env:GOOGLE_PLACES_API_KEY="your-key-here"`
   - **Mac/Linux:** `export GOOGLE_PLACES_API_KEY="your-key-here"`
5. Run `python app.py` as usual — the Find a Doctor page will now show a "🔴 Live search is enabled" message and return real-time results.

If no key is set, the app works exactly as before with the curated static list — no setup required for a basic demo.

## 🚑 Emergency nearest-hospital finder

The "🚑 Emergency" nav link (and the emergency banner shown after a critical
symptom combination) opens `/emergency-hospitals`, which:

1. Asks the browser for the person's live GPS location (`navigator.geolocation`).
2. Plots it on an interactive map (Leaflet.js + OpenStreetMap tiles — free, no API key).
3. Calls `/api/nearby-hospitals?lat=..&lng=..`, which looks up real nearby hospitals via OpenStreetMap's free Overpass API by default, or the Google Places API automatically if `GOOGLE_PLACES_API_KEY` is set (falling back to OpenStreetMap if that call fails).
4. Lists each hospital with distance and a one-tap "Directions" link (opens Google Maps turn-by-turn navigation from the person's current location).

This works with **zero configuration** — no API key needed for the free OpenStreetMap path. It also displays India's national emergency number (112) and ambulance number (108) prominently at the top of the page.

## 🛠️ If live location search doesn't return results

The free OpenStreetMap path now automatically tries 3 different public
Overpass servers in sequence if one is slow or briefly down, and logs what's
happening in the terminal where `python app.py` is running (look for lines
starting with `[overpass]`). If it still doesn't work for you:

1. Open your browser's DevTools (press F12), go to the **Console** tab, and try the location button again — it will print the exact error.
2. Check the terminal running `python app.py` for `[overpass]` log lines — they show which server was tried and why it failed.
3. For much more reliable results, set up the free Google Places API key (see below) — the app automatically uses it instead of OpenStreetMap whenever it's configured.
4. Location search only works on `localhost` or over HTTPS — make sure you're opening `http://localhost:5000`, not an IP address.

## 🎯 Condition-aware live doctor search

A report's "Recommended specialist" line now links straight to a live,
GPS-based search for that exact specialty (e.g. a Cardiologist recommendation
links to a live search for cardiologists near the person's current location,
not just a generic city search). This uses `/api/nearby-specialists`, which:

- Uses Google Places Nearby Search with the specialty as a keyword, if `GOOGLE_PLACES_API_KEY` is set.
- Otherwise falls back to OpenStreetMap's free Overpass API, doing a best-effort name/tag match for the specialty and ranking matching clinics first, with nearby hospitals/clinics shown as a backup if nothing matches exactly.
- Plots results on an interactive map with one-tap directions, exactly like the emergency hospital finder.

The "Find a Doctor" page also has a manual city-text search as a fallback,
plus the curated Agra/Mathura directory, so the feature degrades gracefully
with zero configuration.

## 🛡️ Ethical & safety notes (built in)

- Results are always framed as **"most likely conditions,"** never a definitive diagnosis.
- Medication information is explicitly informational, with a visible disclaimer.
- Emergency symptom combinations trigger a prominent warning banner.
- The specialist directory is clearly labeled as sample/demo data, not real clinics.
- Patient data is stored **locally only** (SQLite) — no external transmission.
- Passwords are hashed (never stored in plain text) via Werkzeug's security utilities.
